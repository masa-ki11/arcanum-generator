# 奥義割り振りツール(戦国炎舞 合戦用)

合戦で設定する奥義を決めて、その日参戦する連合員へ担当を割り振るデスクトップアプリ。
1つの奥義に既定で2人ずつ担当をつけるので、片方が奥義を出せなくても穴が空かない。

標準ライブラリ(tkinter)のみで動くので、外部パッケージのインストールは不要。

Windows と macOS の両方で動く。

## 起動

| OS | 方法 |
|---|---|
| Windows | `run.bat` をダブルクリック |
| macOS | `run.command` をダブルクリック |

macOS で「アクセス権がありません」と出る場合は実行権限が落ちている。
リポジトリには `100755` で入れてあるが、zipで受け取ったときなどは付いていないので、
その場合だけ一度実行する。

```bash
chmod +x run.command
```

コマンドから起動する場合:

```
# Windows
.venv\Scripts\python main.py

# macOS
.venv/bin/python3 main.py
```

素の `python main.py` だと `.venv` ではなくマシン既定の Python で動くので、`.venv` 側を指定すること。

## 環境構築(`.venv` が無いとき / 別のPCに持っていったとき)

外部パッケージは使っていないので、Python と tkinter さえあれば `.venv` を作るだけで終わる。

### Windows

```
winget install --id Python.Python.3.14 -e --scope user
py -3.14 -m venv .venv
```

### macOS

**python.org の公式インストーラを使うのが確実**(Tk 8.6 が同梱される)。
<https://www.python.org/downloads/macos/> から 3.14 を入れて:

```
python3.14 -m venv .venv
```

Homebrew の Python を使う場合は tkinter が別パッケージなので、先にこれが要る:

```
brew install python@3.14 python-tk@3.14
```

macOS 標準の `/usr/bin/python3` は Tk が古く表示が崩れることがあるので避ける。

### 確認

```
.venv/bin/python3 -c "import tkinter; print(tkinter.TkVersion)"   # 8.6 以上ならOK
```

動作確認は Python 3.14.6 / Windows 11 で実施。macOS 側は未実機検証(下記「未確認事項」参照)。

## 使い方

1. **左:合戦で設定する奥義** — 奥義名・種類・必要人数(既定2)・前半必須を入れて「追加」。
   行を選ぶと下の入力欄に内容が入るので、直して「選択中を更新」で編集できる。
   ↑↓で並べ替え、「種類ごとにまとめる」で種類順に整列。
2. **中央:連合員 / 本日の参戦** — 名前を追加(「まとめて追加」で改行区切り一括貼り付け可)。
   参戦状況は**1戦目・2戦目・3戦目それぞれ**に持つ。変え方は3通り。
   - **戦の列をダブルクリック** … その戦だけ ◎→〇→△→×→－ と送る
   - 「対象」で戦を選び、行を選んで「選択→ ◎ 〇 △ × －」… 複数人まとめて指定
   - 「対象」で戦を選び「全員◎」「全員×」「全員－」… 全員まとめて指定

   「対象」を**全戦**にしておけば3戦まとめて指定できる。まず全戦で埋めてから、
   出られない戦だけ列をダブルクリックで直すのが早い。

   **前衛**も戦ごとに設定する。`前1`〜`前3` の列をダブルクリックでその戦だけ切り替え、
   「対象」で戦を選んで「前衛」ボタンを押せば選択中のメンバーをまとめて切り替えられる。

   軍師は行を選んで「軍師」ボタン。**軍師には奥義を割り当てない**。

   **↑↓ で並べ替え**できる。複数選択したままでも、まとまりを保って動く。
   ここで決めた並び順が、結果の「メンバー別」やCSV・コピーの出力順になる。
3. **上部:1人あたりの奥義枠** — 1人が何個まで奥義を担当できるか。全員共通。既定は4。
4. **「割り振る」** — 右に結果が出る。押すたびに組み合わせが振り直される。
5. **「結果をコピー」** で連合チャットに貼れるテキスト、**「CSV出力」** でExcel用CSV。

結果の **「奥義別」は種類ごと**にまとめて出る。**「メンバー別」は連合員の並び順**
(中央パネルの上から順、軍師を除く)で出る。CSV・コピーも同じ順番。

## 自動保存

入力内容は**変更のたびに自動でプロジェクトフォルダの `kassen.json` に保存される**。
次に起動したときは自動で読み戻すので、保存操作は要らない。ウィンドウを ✕ で閉じても消えない。

- 保存先は画面下に常時表示している
- 保存先は**このファイルの位置から決めている**(カレントディレクトリに依存しない)。
  macOS で Finder から `.command` をダブルクリックするとカレントがホームになるため
- 書き込みは一時ファイル経由。途中で落ちても前回の内容が壊れない
- `kassen.json` が壊れていた場合は `kassen.json.broken` に退避してから空で起動する
  (壊れた内容を黙って上書きしない)

**「別名で保存」** は自動保存とは別の控えを取る機能。**「読み込み」** で控えを戻せる
(戻した内容はそのまま自動保存にも反映される)。

## 奥義の種類

奥義には次の4種類がある。種類によって割り振りの扱いが変わる。

| 種類 | 扱い |
|---|---|
| 絆 | 必要人数ちょうど |
| 一定 | 必要人数ちょうど |
| 瞬時(一度のみ) | 必要人数ちょうど |
| **瞬時(何度も)** | **必要人数を持たない。余った枠に入れるだけ** |

「瞬時(何度も)」は必ず入れなければならない奥義ではないので、**枠を先取りしない**。
他の奥義を配り終えたあとに残った枠を吸収する。0人になっても不足扱いにしない。
そのため必要人数の入力欄は無効になり、一覧では `—` と表示される。

ただし**1人が同じ奥義を2回持つことはできない**ので、1つの奥義に付けられる上限は人数まで。
**この種類だけは×や－の人にも配る**(来たら出せるので、余らせるより設定しておく)。

たくさん入れさせたいときは「瞬時(何度も)」の奥義を足す。

## 1日3戦と「奥義は変えない」制約

1日の合戦は**3戦**ある。参戦状況は戦ごとに設定するが、
**奥義は1日通して変えない**。したがって割り振りは1回だけ行い、その結果を3戦すべてで使う。

このため、担当者の選び方は次のようにしてある。

- **どの奥義も、各戦に「確実に出せる担当(◎〇)」が1人以上いるようにする。**
  2人いても両方が同じ戦を欠けばその戦は穴になるので、
  **人数を揃えることより穴を塞ぐことを優先**する。
  塞ぐために必要人数を超えて3人・4人になることもある
- **△は埋まったとみなさない。** △は来ないことがあるので、
  「△の人だけがその戦に出られる」状態は穴とみなして◎〇の人を足しにいく。
  ◎〇で埋められる人が誰もいない場合にかぎり、何も入れないよりましなので△を入れる
- **前半必須(★)の奥義は、どの戦にも◎の担当が1人以上いるようにする。**
  各戦バラバラの◎しかいなければ3人必要になる。
  全戦◎の人が1人いれば、その人だけで3戦ぶんまかなえる

担当者を選ぶ際、担当数が同じ人が並んだときは
**まだ確実に出せる人がいない戦を埋められる人を優先**する。これにより多くの場合、
人数を増やさずに穴が塞がる。

### 結果表の「確実 1/2/3戦」列

戦ごとの状態を1文字で表す。

| 表示 | 意味 |
|---|---|
| 数字 | その戦に**確実に出せる担当(◎〇)**の人数 |
| **△** | ◎〇の担当がおらず、**△頼み**になっている(橙色 + 警告) |
| **×** | 誰も出られない(赤字 + 警告) |

`1/△/2` なら「2戦目は△の人しか出せない」という意味。
△や×が出るのは、その戦に出られる人がそもそも足りていないとき。
連合側で参戦者を増やすか、奥義の数を減らすしかない。

## 奥義に付ける印

奥義一覧と結果表の「印」列に出る。

| 印 | 意味 | 割り振りでの扱い |
|---|---|---|
| **★** | 前半必須 | どの戦にも**◎の担当**が1人以上いるようにする |
| **前** | 前衛に割振 | **前衛の人にしか割り当てない**。加えて、どの戦にも前衛の担当が1人以上いるようにする |

どちらも他の奥義より先に処理され、**必要人数を超えて担当が増えることがある**。
前衛は戦ごとに変わるので、1戦目だけ前衛の人・2戦目だけ前衛の人…と分かれていれば
その数だけ担当が必要になる。全戦とも前衛の人が1人いれば、その人だけでまかなえる。

**`前` の奥義に後衛の人が入ることはない。** ここでいう前衛とは
「**前衛に設定されていて、かつその戦に参戦する**」人のこと。前衛に設定されていても
3戦とも×か－なら対象外。前衛が足りなければ後衛で埋めるのではなく、
担当を減らして警告を出す(「瞬時(何度も)」の余り埋めでも後衛には配らない)。

埋めきれなかった戦がある場合は橙色の表示と警告を出す。両方の印を付けることもできる。

## 参戦状況と軍師

参戦状況は1戦目・2戦目・3戦目それぞれに持つ。

| 表示 | 意味 | 扱い |
|---|---|---|
| ◎ | その戦の前半から確実に参戦 | 優先して割り当てる。前半必須の奥義はここから充てる |
| 〇 | 参戦 | ◎に次いで割り当てる |
| △ | 参戦できるか不明 | **◎〇だけでは足りないときにかぎって**使う。**その戦が埋まったとはみなさない** |
| × | 不参戦 | 必要人数の確保には使わない。「瞬時(何度も)」の余り埋めのみ |
| － | 未回答(既定) | 同上 |

3戦のうち**どこか1戦でも◎〇があれば**優先枠、どこか1戦でも△があれば予備枠として扱う。
**3戦とも×か－の人**は必要人数の確保には使わず、「瞬時(何度も)」の余り埋めにだけ入る。

**軍師**に指定した人は、参戦状況にかかわらず一切割り当てない。

### 前衛

前衛かどうかも戦ごとに設定する(`前1`〜`前3` の列)。参戦状況と同じく、
1戦目だけ前衛、といった持ち方ができる。

奥義側で **`前` 前衛に割振** を付けた奥義は、この設定を見て担当を決める(下記)。

画面下のステータスバーに戦ごとの前衛人数が出る。
**連合員の前衛設定そのものは出力(CSV・コピー用テキスト・結果のメンバー別)に含めない。**
割り振りの入力として使うだけで、連合員パネルで設定・確認する。

## 割り振りのルール

6段階で配る。「瞬時(何度も)」は段階1〜5では一切枠を取らない。

1. **「瞬時(何度も)」以外の全奥義に1人ずつ確保**する。★と`前`の奥義を先に処理する。
2. **★の奥義に、各戦の◎が1人以上入るまで**担当を足す。
3. **`前`の奥義に、各戦の前衛担当が1人以上入るまで**担当を足す。
   `前`の奥義は全段階を通じて前衛の人しか候補にしない。
4. **どの奥義も、各戦に確実に出せる担当(◎〇)が1人以上いるまで**足す。
   ◎〇で埋まらない戦だけ、最後に△でも入れておく。
5. 余裕のある奥義から**必要人数(既定2人)まで増やす**。
6. 残った枠を**「瞬時(何度も)」で埋める**。この段階だけ×や－の人にも配る。

段階2〜4は必要人数を超えることがある。穴を塞ぐほうが人数を揃えるより優先。

そのうえで、

- 同じ奥義に同じ人は入らない。1人あたりの担当数は「1人あたりの奥義枠」まで。
- 担当数はできるだけ均等にする。
- 担当数が並んだときの順番は奥義ごとにシャッフルする。順番を固定すると同じ2人組が
  複数の奥義に入り続けてしまい、その2人が同時に落ちたときまとめて穴が空くため。

### 人手が足りないとき

**◎〇△を集めても2人体制を組めない場合、足りない分だけ1人担当に落として成立させる**
(エラーで止めない)。全奥義を最低1人でカバーすることを優先し、余裕のある奥義から
2人目を付ける。1人担当になった奥義は結果に赤字で出て、警告にも一覧が出る。

### 割り振れない場合

次のどれかに当てはまるときだけ、理由を出して割り振りを中断する。

- 奥義が0件
- 割り当てられるメンバーが0人(軍師を除いた◎〇△が誰もいない)
- 奥義名またはメンバー名が重複している
- 奥義の種類や参戦状況が規定の値以外になっている(ファイルを手で編集したときなど)
- 必要人数や1人あたりの枠数が0以下

画面下のステータスバーに参戦状況の内訳と「割当可 ◯人 × ◯枠 = ◯枠」が常に出るので、
足りているかは押す前に確認できる。割り振ったあとは「使用 ◯枠 / うち余り埋め ◯枠 /
必要人数に届かず ◯件」に変わる。

## 構成

```
run.bat                        Windows用ランチャ
run.command                    macOS/Linux用ランチャ
kassen.json                    自動保存ファイル(実行すると作られる)
main.py                        起動口
pyproject.toml                 プロジェクト設定(requires-python >= 3.14)
.python-version                3.14
arcanum_generator/
  models.py                    奥義・連合員・入力一式のデータ構造
  allocator.py                 割り振りロジックと入力チェック
  storage.py                   JSON保存/読み込み、CSV・テキスト出力
  gui.py                       Tkinterの画面
tests/test_allocator.py        ロジックのテスト
```

割り振りロジックは画面から独立しているので、`allocate(roster)` を直接呼んでも使える。
